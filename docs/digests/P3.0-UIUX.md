## 9.1 Design Principles (6 principles — verbatim intent)
- **Safety first** — interface actively prevents clinical error: allergy + interaction alerts, explicit confirmation for destructive/irreversible actions, unambiguous status. Patient banner and alerts always visible during clinical work.
- **Speed for repeat users** — frequent tasks (register, book, check-in, document, dispense, bill) reachable in fewest interactions; keyboard support, sensible defaults, inline creation over page hops.
- **Clarity over decoration** — restrained healthcare palette, generous whitespace, strict type scale; colour carries meaning (status) never decoration alone.
- **Consistency** — one shell, one component library, one set of interaction patterns across all 31 modules; learned behaviour transfers everywhere.
- **Context, not navigation** — active patient, branch, and encounter travel with the user; progressive disclosure to drawers.
- **Inclusive by default** — WCAG 2.1 AA, full keyboard operability, localisation incl. RTL are baseline, not enhancements.

## 9.2 Design Language & Visual System
Design decisions encoded as **tokens** (colour, type, spacing, radius, elevation, motion) consumed by **Tailwind** and the **ShadCN** component layer. Single source re-themes the entire product; tenants branded without code changes (per Section 9.13).

### Colour Roles (Table 9.1 — light theme; dark theme maps same roles)
| Token | Value (hex) | Use |
| --- | --- | --- |
| primary | `#1F4E79` | Primary actions, headers, active nav, key figures |
| secondary | `#2E86AB` | Links, secondary emphasis, informational accents |
| accent | `#148F77` | Positive primary CTAs (save/confirm), success |
| warning | `#C9821B` | Caution states, waiting, near-expiry, pending |
| danger | `#C0392B` | Errors, destructive actions, critical clinical alerts |
| muted | `#6B7280` | Secondary text |
| border | `#D5DCE5` | Dividers |
| surface | `#F2F7FB` | Panel and row backgrounds |

### Typography (Table 9.2 — Type scale)
- Single UI typeface: **Inter**, with **system-UI fallback stack**.
- Numerals are **tabular** in tables and totals.
- Reading-area line length capped at **~70–75 characters**.

| Style | Size / Weight | Usage |
| --- | --- | --- |
| Display / H1 | 26px / 700 | Page titles |
| Section / H2 | 21px / 700 | Section headers within a page |
| Subsection / H3 | 17px / 700 | Card and group titles |
| Body | 14px / 400 | Default content |
| Small / caption | 12px / 400 | Helper text, metadata, table captions |
| Micro / label | 10.5px / 700 | Field labels, chips, eyebrow text |

### Spacing, Grid, Elevation, Motion, Iconography
- **Spacing**: 8px base grid; steps `4 · 8 · 12 · 16 · 24 · 32 · 48`. **12-column** responsive grid with a max content width on very wide screens.
- **Radius**: `4px` inputs/cells · `8px` cards · `14px` modals · `pill` chips/toggles.
- **Elevation**: 4 levels — `0` flat · `1` card · `2` popover/menu · `3` modal/dialog — soft shadows; **never used to imply status**.
- **Motion**: `120–160ms` ease-out for entrances; `90ms` for state changes; respect `prefers-reduced-motion` (disable non-essential animation).
- **Iconography**: **Lucide** line-icon set, **1.5px** stroke, **16/20/24px** sizes; always paired with text label or accessible name.

## 9.4 Application Shell & Navigation
Every authenticated screen renders inside **one shell**. Layout regions:
- **Top bar**: brand, global search/command palette, branch scope switcher, notifications, help, account.
- **Left navigation rail**.
- **Primary work area**.
- **Optional right context drawer** — carries active patient/encounter.

Shell behaviours:
- **Branch scope switcher** — multi-branch users switch active branch from top bar; selection **scopes data, defaults, and permissions across the session** (per RBAC scoping).
- **Role- and flag-gated navigation** — nav items render only when user's role permits AND tenant's feature flag is enabled; disabled modules are **hidden**; direct access shows an **upgrade prompt** rather than a dead end.
- **Global search / command palette** — `Ctrl/Cmd-K` opens unified search across **patients, appointments, invoices, and navigable actions**.

## 9.6 Interaction Patterns

### Forms & validation
- Labels always visible (**no placeholder-only fields**); required fields marked; helper text beneath field.
- Validation inline and on **blur/submit**; first error focused and summarised; field errors use **danger token + icon** (never colour alone).
- Long forms use **steppers** with progress, **save-as-draft**, and **resumable state**; **unsaved-change guards** prevent accidental loss.
- **Dynamic forms** render from the **versioned JSON schema (Section 6.6)** using the same field components and validation affordances.

### Data tables
- Sticky headers, **server-side** sort/filter/paginate, saved filters, column density toggle, per-row and bulk actions; selection reveals a contextual action bar.
- Numbers **right-aligned and tabular**; status shown as coloured pills; **row click opens detail in a drawer** where possible to preserve list context.

### Overlays & feedback
- **Drawers** for contextual detail/edit (keep list visible); **modals** only for focused, blocking decisions; **bottom sheets** on mobile.
- **Toasts** confirm transient success + offer undo where feasible; **banners** carry persistent state (e.g., outstanding balance); **inline alerts** attach to field/section.

### Four mandatory screen states (every screen)
| State | Implementation requirement |
| --- | --- |
| Loading | **Skeletons, not spinners**, for content regions |
| Empty | Explainer + primary action |
| Error | Cause + retry |
| Populated | Designed explicitly, never left to default |

## 9.10 Responsive & Device Strategy (Table 9.6)
**Desktop-first** for staff workstations; fully responsive down to **tablet** for clinical capture and **mobile** for patient portal + quick actions.

| Breakpoint | Layout behaviour |
| --- | --- |
| ≤ 640px (mobile) | Single column; left nav → drawer / bottom tab bar; tables collapse to cards; bottom sheets for actions |
| 641–1024px (tablet) | Two-pane; collapsible nav; touch targets ≥ 44px; optimised for vitals/queue capture |
| 1025–1440px (desktop) | Persistent sidebar + work area; context drawer on demand |
| > 1440px (wide) | Content max-width centred; context drawer can pin open; denser tables |

## 9.11 Accessibility (WCAG 2.1 AA)
- Colour contrast meets AA: **≥ 4.5:1** text, **≥ 3:1** large text and UI boundaries; status conveyed by **icon/text as well as colour**.
- Full keyboard operability: logical tab order, visible focus rings, **skip-to-content**, **no keyboard traps**; shortcuts for high-frequency actions.
- Semantic HTML + ARIA: landmarks, labelled controls, described errors, **live regions** announcing async updates (e.g., queue changes, save confirmations).
- Touch targets **≥ 44×44px**; forms support autofill + assistive tech; modals **trap and restore focus**.
- Respects `prefers-reduced-motion` and `prefers-color-scheme`; text resizes to **200%** without loss of function.

## 9.12 Localization, Internationalization & RTL
- All copy externalised for translation; **no concatenated strings**; pluralisation + gender handled via i18n library.
- Locale-aware dates, numbers, currency; timestamps shown in **branch/user timezone** but **stored UTC**.
- Full **RTL** support: layout mirrors (nav, alignment, icons) when RTL locale active; components direction-agnostic.
- Layouts tolerate **~30–40% text expansion** without truncation/overflow.

## 9.13 Theming & Multi-Tenant Branding
- Tenants configure **logo, primary/accent brand colours, document letterhead** from Admin; app re-themes from tokens **at runtime — no redeploy**.
- Brand colours **validated for contrast**; if a chosen colour fails AA against required surfaces, UI **substitutes an accessible shade and warns the admin**.
- Light + dark themes share same semantic token roles; **printed/PDF documents (invoices, prescriptions, reports) inherit tenant branding**.

## 9.14 Microcopy & Content Guidelines
- Plain, clinical-appropriate language; verbs for actions ("Sign & close", "Record payment"); avoid jargon in patient-facing surfaces.
- Error messages state what happened + how to fix; never blame user; empty states explain value + offer next action.
- Confirmations name the consequence (e.g., "Delete 3 draft invoices? This cannot be undone."); destructive verbs explicit.
- **Sentence case** for UI text; consistent terminology from project glossary (e.g., "encounter", "branch", "claim").

## 9.15 Notifications & Feedback Patterns (Table 9.7)
| Channel | When | Pattern |
| --- | --- | --- |
| Toast | Transient outcome of a user action | Auto-dismiss; optional undo; bottom/top corner |
| Inline alert | Field- or section-level issue | Attached to relevant control; persists until resolved |
| Banner | Persistent contextual state | e.g., outstanding balance, module disabled, system notice |
| In-app notification centre | Async events for the user | Bell with unread count; deep-links to the record |
| Email / SMS | External reminders & results | Appointment reminders, result-ready, receipts (per prefs) |

## 9.16 Design-to-Development Handoff
- **Single source of truth**: tokens + components defined once, consumed by both design (library) and code (**Tailwind + ShadCN**) for parity.
- Each component ships with documented **props, all states, usage do/don't, accessibility notes**; screens specified with responsive behaviour + the four content states.
- Acceptance includes **visual regression and accessibility checks in CI**; deviations from tokens flagged in review.
