## 10.2 Role Hierarchy & Configuration Cascade
- Configuration is **strictly top-down**: SaaS owner provisions tenant + assigns plan → tenant owner configures clinic (branches, departments, users, flags, branding) → branch managers / department leads configure their areas → end-user experience = sum of those decisions + their role.
- **Hard invariant:** "No user can grant themselves capabilities above their tier."
- Tenant provisioning + first-run config follow a **guided sequence** (Fig 10.2): tenant creation by SaaS owner → tenant owner onboarding wizard → go-live.

## 10.3 Shared Authentication & Session Experience
- **Single auth experience for all roles**, differentiated only by **entry URL** and **post-login routing**.
  - **Tenant users:** sign in at their **workspace = tenant subdomain**.
  - **Platform staff:** sign in at a **separate admin domain**.
- **MFA policy:**
  - **Mandatory** for: all platform staff; any tenant role with **administrative or financial** privileges.
  - **Optional-but-encouraged** otherwise.
- **Login screen elements (Fig 10.3):**
  - **Workspace field** — pre-filled from subdomain; lets shared-device users confirm tenant; platform staff see platform context instead.
  - **Credentials + SSO** — email + password, or **SSO (SAML / Google)** when tenant has configured it; **"keep me signed in"** respects **device-trust policy**.
  - **MFA step** — when enabled, a **6-digit TOTP** step follows; **recovery codes** and **"trust this device"** available.
- **Login states (explicit):**
  - Inline error for invalid credentials with **no account enumeration**.
  - **Lockout** after repeated failures.
  - **Password-reset** link.
  - **Disabled-account** and **suspended-tenant** messages.
- **Post-auth:** system resolves **tenant, role, and scope**, then routes to role-specific landing page. **Session refreshes silently** and **re-prompts on expiry** (Fig 10.4).

## PLATFORM TIER

### 10.4 SaaS Owner (Platform Owner)
- **Scope:** highest-privilege platform account. Owns every tenant, subscription plans, platform-wide settings, billing, platform team. **Cannot read individual patient clinical data** without an **explicit, consented, audited support session (impersonation)**. Sees **aggregate, not clinical** info by default.
- **Login/entry:** admin domain, **mandatory MFA** → lands on **Platform Overview**.
- **Landing:** portfolio KPIs (**active tenants, MRR, trials, churn, API volume**), recent-tenants table, system-health indicators, attention list (**past-due accounts, ending trials, plan-limit breaches**).

| --- | --- | --- | --- |

| Tenants — list | Find & manage all tenants | Search/filter by **plan/status/region**; columns: plan, branches, users, MRR, status; row → detail | Sortable, paginated |
| Tenant — detail | Inspect & administer one tenant | Account info; plan & limits; feature flags; usage; activity; actions: **change plan, impersonate, suspend/cancel** | Actions **audited** |
| Create tenant | Provision a new account | **Name, slug/subdomain, plan, region, owner email** → sends owner invite | Validation; **idempotent** |

### 10.10 Doctor / Physician
- **Scope:** clinical work for their patients within assigned **branch(es)/department(s)**: consultations, EMR, prescriptions, orders, results review. Sees clinical data for in-scope patients; **no platform or billing administration**.
- **Login/entry:** workspace subdomain; **MFA per tenant policy** → **"My day"** (schedule + patients waiting).
- **Landing:** my schedule, patients waiting in queue, pending results to review, **unsigned notes**.

**Permission principles (enforcement rules):**
- Every screen and action is **gated server-side** by **role + scope (branch/department) + feature flag**.
- UI **hides** what a user cannot do (no disabled dead-ends) — **except** flag-gated modules, which show an **upgrade prompt to admins**.
- Scope **narrows data** to assigned branch(es)/department(s).
- **Cross-tenant access is impossible by construction** (Sections 5.7, 8.9).
- **All privileged and clinical actions are audited.**

## Cross-Cutting Engineering Notes
- **MFA enforcement matrix:** platform staff (all) = mandatory; Tenant Owner/Admin = mandatory; Accountant = mandatory; Cashier, Doctor, Branch Manager, HR Manager = "per policy"/"recommended"; Patient = email/phone + password or one-time code (MFA optional in profile).
- **Audit / append-only stores:** Platform Audit, Super Admin Audit log, Tenant Owner Audit log are all **append-only/immutable**. Impersonation, flag overrides, plan changes, suspensions, dispense, stock adjustments, refunds, void/adjust, transfers, stock counts are explicitly audited.
- **Impersonation:** consented, **time-boxed, read-only-by-default, auto-expiring**, with **persistent banner** while active; full audit. Available to Super Admin + Support.

  - **Grafana** — System Health screen (10.4) links out to Grafana for API latency/error rate, queue depth, DB replication, region status.
  - **Background-job queues / workers / dead-letter** — Super Admin "Background jobs" (10.5): per-queue status, retries, dead-letter, requeue/inspect failed jobs (e.g., failed report-generation jobs). Generic queue infrastructure; no specific broker (Redis/RabbitMQ/etc.) named in this part. **DB replication** monitored on System Health (implies replicated primary DB), but the engine is not named here. No explicit mention of Redis, RabbitMQ, OpenSearch, S3, or Kubernetes by name in this document part.
  - **Email/SMS providers** — configured in Platform Settings (10.4) and Tenant Settings (10.8); SMS counted as a metered usage dimension.
