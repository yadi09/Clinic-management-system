Staff login: UI/UX redesign plan

ClinicOS · plan for approval · 2026-11-14 · nothing built yet

In one line: make the page know which clinic you are signing in to. Staff type the clinic code once on a device (or open a clinic's own link). After that, every day is just email → password → in, on a screen that shows the clinic's name and logo. Errors explain what to do next.

1. What exists today

Yes, it is a single shared login page. Every clinic and every branch uses the same /login. The clinic is not in the address. The person picks it by typing a Workspace (the clinic's slug, e.g. cure-dental). Since FEAT-BRANCH-WS-1, each branch is a separate workspace with its own slug, so a two-branch clinic has two different words to type.

3. Proposed experience

The flow: clinic first, then you

① Which clinic?(skipped when already known)→② Sign in to Cure Dental→③ 6-digit code(only if MFA)→Home

Step ① is skipped automatically when the clinic is already known, which covers almost every day:

  • From the address: clinicos.cc/login/cure-dental (or ?clinic=cure-dental). A clinic gives its staff this link, or bookmarks it on the front-desk PC.
  • From this browser: after a successful sign-in, the browser saves that clinic code (only the code, never the email or password). Next time the page opens already set to "Cure Dental", with a Change link.

So a receptionist's normal morning is open the bookmark → email (often prefilled by the browser) → password → in, on a page that shows their clinic's name and logo.

Screen ① Enter clinic code (only the first time in this browser, or after "Change")

There is no list of clinics anywhere. Each browser remembers only the one clinic code last signed in to there. A new visitor, or a browser that has never signed in, sees an empty field.

Error and status messages (rewritten)

Each message says what happened and what to do next. The security rule stays: we never reveal whether an email exists.

CaseNew message
Wrong clinic code / email / password

Locked out
Too many wrong tries. This account is paused for 15 minutes to keep it safe. Wait, or ask your clinic admin for a reset link.

Interaction details

  • Focus goes to the first empty field. Enter submits. The button shows a spinner and stays disabled while signing in, so there are no double submits.
  • The clinic code is cleaned as you type (lower-case, spaces become -) to match the server.
  • The browser stores one clinic code, and only after a sign-in succeeds, so a typo is never remembered. "Change" clears it. Owners with several branches sign in to one and move between branches with the in-app switcher, as they do today.
  • Email is left to the browser's password manager (autocomplete="username"). We don't store it ourselves, because front-desk PCs are shared.
  • The page keeps sending people back to where they were going after sign-in, as it does today.
  • Accessibility: real labels, errors linked with aria-describedby, an announced alert region, 44px touch targets, and AA contrast in light and dark.
