Working on ClinicOS for $20 a month

How to make the Pro plan enough — and what it costs you if you don't

The single biggest change is not the model you pick. It is that one session ran from 5 to 24 September. Every message in a long session re-sends everything before it, so by the end a one-line question costs more than a whole task did on day one. Short sessions are worth more than every other habit on this page combined.

Four things drove that, in order of size:

WhatWhy it costs
Context piling up A conversation carries its whole history on every turn. At the end of a three-week session, asking "is it deployed?" costs more than building the entire campaign page did on day one.

02The five habits, in order of what they save

Biggest 1 — One session per task. Then close it.

Finish a task, then /clear or quit. Start the next one fresh. This is worth more than everything else here put together.

You lose almost nothing by doing it: your 39 memory files in ~/.claude/ carry the important things across — the deploy key, the Addis timezone rule, the commit-author rule. A fresh session already knows them.

A rough guide: if you have been in the same session more than a couple of hours, or you have moved on to an unrelated task, close it.

Large 2 — Sonnet by default. Opus when it is genuinely hard.

/model switches mid-session. Start on Sonnet and move up only when you hit something that needs real thought.

Worth OpusSonnet is fine
Designing the draw fairness · finding why money is wrong · a bug that survived two fixes · auditing something you are about to publish · architecture decisions Adding a field to a form · writing a migration from your description · fixing a type error · running a deploy · writing tests from a spec · renaming things · CSS

Honestly: in this project, the fairness algorithm, the money-projection bug and the plan-entitlement model needed Opus. Most of the rest did not.

Large 3 — Tell me where to look
costs a lot"The unbilled report is broken, can you check?"
costs a little"The unbilled report 500s. It's in backend/internal/dental/service/. Probably the SQL."

You know this codebase. Every file path you give me is a search I do not run and a file I do not read to find out it was the wrong one.

Medium 4 — Create a CLAUDE.md once

There isn't one. That means every new session rediscovers the same facts: that sqlc is not installed so queries must be raw pgx, that RLS needs WithTx, that the clinic's day is Addis and not UTC, that migrations are goose and numbered.

Written down once, those stop costing anything. It is a twenty-minute job that pays back every session for the life of the project — and it is the reason habit 1 works so well, because a fresh session starts already knowing the rules.

Medium 5 — Say when you don't need proof

By default I verify: run the tests, check the deployed page, screenshot the result. That is right for money and patient data. It is overkill for a CSS change.

say this for small things"Just make the change, I'll check it myself."

And when something does need checking, prefer "run the campaign e2e" over "make sure everything still works" — one is a command, the other is an open invitation.

03What not to economise on

Being too frugal costs more than it saves. Two real examples from this project:

  • The staff table lost its email column. Build passed, types passed, all 30 API tests passed. Only opening the actual page in a browser caught it — six headers over five cells, every column under the wrong heading.
  • Every quiz answer was A. Nothing automated would ever have flagged it. The campaign would have taught dental clinics nothing, which was its entire purpose.

So: keep the verification for money, patient data, and anything a customer sees. Skip it for internal tools, styling, and work you will look at yourself in a minute anyway.

04A week that fits in $20

SessionModelShape
A featureSonnet, Opus if the design is unclear Describe it, name the files, let it build, close the session.
A bugSonnet first Paste the error and the file. Move to Opus only if Sonnet's second attempt misses.
A deploySonnet It is one command now. This needs no thinking at all.
A decisionOpus Pricing, architecture, anything you will live with for a year. Short session, worth every token.

Four or five short sessions a day at this shape is comfortable on Pro. One session left open all week is not.

05Signs you are burning it

  • The same session has been open since yesterday
  • You are on Opus and the task is "change the button colour"
  • I am reading files you could have named
  • I am taking screenshots of something you can see on your own screen
  • I am re-running a full test suite to confirm something I already confirmed

Any of those: say "switch to Sonnet", or "/clear and start fresh", or "stop verifying, I'll check". All three are fair, and none of them offend me.

06When $20 stops being enough

Be honest with yourself about the signal. Upgrade when you are repeatedly stopped mid-task — not when you are merely aware of the limit. Being cut off halfway through a deploy on a system holding 677 patient records costs more than the difference in plans.

Until then, Pro genuinely works for this project. The habits above are not a compromise — short sessions and the right model produce better work anyway, because a fresh session with good standing context is sharper than a three-week-old one carrying everything that ever happened.
